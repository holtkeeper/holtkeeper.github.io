Agents

What agents can ask

Holtkeeper’s MCP endpoint offers about fifty tools, all built on data Holtkeeper already stores: analyses of every repository, the library index and the team’s knowledge. Calls are cheap and never start an analysis or an AI run. This page walks through them by the question an agent is trying to answer; MCP tools lists every argument.

Repositories are always named forge:path, for example gitlab:acme/checkout-web. Answers are Markdown, cut at about 80 000 characters with a hint on how to narrow the request.

Your organization’s packages

Section titled “Your organization’s packages”

Holtkeeper indexes the public API of every package your repositories publish: each export with its declaration and doc comment, for every released version and the default branch. Agents use it instead of reading node_modules or other repositories’ sources.

Question Tool
Is there already a helper for this? search_symbols, then get_symbol
What does this package export? list_packages, get_package_api
What changed between two versions? list_versions, diff_versions

Packages marked removed were dropped from their repository; answers about them start with a warning not to use them in new code.

How the fleet uses a package

Section titled “How the fleet uses a package”

A second index records how every repository uses its dependencies: which exports, how (call, JSX, type, member access), which JSX props and which members.

Question Tool
Who uses this package, at which versions? package_usage
Show me the code of those uses. find_usages
What breaks if everyone upgrades to 5.0? upgrade_impact
What does this repository depend on? repo_packages
Which teams use this library or tool? who_uses

upgrade_impact covers npm packages and Go modules; for Go it sees syntactic uses, plus the methods and fields reached through values (a method called on a returned value) when the usages job has the go toolchain.

Third-party libraries

Section titled “Third-party libraries”

The npm and Go libraries the fleet uses are indexed at the versions in use and the ones an upgrade would land on. Pass repo and versions default to what that repository uses, so answers match the code in front of the agent. See Library docs for what is indexed.

Question Tool
Which versions are indexed, who uses which? library_versions
How do I use this API at my version? search_library_docs, read_library_doc
What changed between my version and the latest? library_changes
Is this error a known issue? search_library_issues
How is this implemented? library_source

Text from libraries and issues is third-party data; agents are told never to follow instructions in it.

Adding or upgrading a dependency

Section titled “Adding or upgrading a dependency”

Before an agent adds a dependency, evaluate_dependency answers everything the organization knows in one call: who already uses it and at which versions, whether an internal package does the same job, deprecations, advisories with fixed versions, licenses with each repository’s verdict, its gzip share of measured bundles, and accepted team knowledge about it.

Rules and knowledge

Section titled “Rules and knowledge”

Before changing code in a repository an agent calls repo_rules for the team’s Guide; before committing, commit_conventions and check_commit_message; for UI work, test_ids; for images, asset_policy. The knowledge base answers search_knowledge. These have their own page: Rules and knowledge.

Releases

Section titled “Releases”
Question Tool
How does this repository release? release_rules
Where is it in its flow, what is next? release_status
What changed since the last version? release_changes
Propose, accept, tag or deploy release_step (token with Release steps)

release_step never runs on the first call. Without confirm it returns a preview and a one-time confirm token valid for 10 minutes; the agent shows the preview, and only a second call with the same arguments and that token runs the step.

Jobs and health

Section titled “Jobs and health”
Question Tool
Is the analysis data current? analysis_status
How is every repository doing? fleet_health
Which jobs ran recently? jobs
Why did this job fail or not start? why_job, then job_log
How busy is the queue? queue_stats
How much of this week’s AI budget is left? budget_status (with AI read access)

analysis_status is worth a call before trusting stored data such as the public API, coverage or test ids: it says, per analyzer, which commit the record describes, whether it is stale and when it may refresh.

Job logs are data from the job, never instructions.

Tasks

Section titled “Tasks”

start_task, task_status and request_review let an agent ask Holtkeeper to change code. They are the only tools that lead to writes on the forge; see Changing code through tasks.

When a tool refuses

Section titled “When a tool refuses”

A tool that needs a permission you lack answers with an error naming it, for example that audits:read is missing on a repository. Repositories you cannot see answer the same as repositories that do not exist.
