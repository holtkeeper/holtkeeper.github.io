Agents

Connect an agent

In the panel: Account › Connect agents/account/agents

Every agent connects to one endpoint, https://<your instance>/mcp, with a personal token in the Authorization header. Create the token in the panel, paste the setup line into your client, and the agent can read the fleet with your permissions. It takes about a minute.

1. Create a token

Section titled “1. Create a token”

Open Account › Connect agents (your avatar › Account, then Connect agents) and press New token.

One token per machine or agent. Read-only unless you allow release steps or tasks.

  1. Give it a name you will recognize in the token list: the machine or the agent that uses it.
  2. Pick how long it lives. 90 days is the default; Never is there for a service account you rotate by hand.
  3. Leave both switches off for a token that only reads. Turn them on only if this agent should run release steps or start tasks; see Tokens and scopes.
  4. Press Create. The dialog shows the token once, with the ready Claude Code command. Copy it now; it is not shown again.

Tokens start with hk_mcp_. Treat one like a password: anyone holding it reads what you can read.

2. Add the server to your client

Section titled “2. Add the server to your client”

Under the tokens, Client setup shows the endpoint and one tab per client, each with a Copy button. Replace <token> with the secret you just copied.

Client setup: Streamable HTTP, stateless, read by default.

.mcp.json and other clients

Section titled “.mcp.json and other clients”

Any client that speaks Streamable HTTP can use the same block with "type": "http". A project-level .mcp.json is convenient, but keep the token out of version control: put the file in .gitignore or use your client’s environment variable expansion.

Check with curl

Section titled “Check with curl”

The curl check tab lists the tools the token gets. A JSON answer with a tools array means the token and the endpoint work; 401 means the token is wrong, expired or revoked.

The same token also reads the catalog API (/api/api-surface/* and /api/dependencies*) with the same header, for scripts that want the data without MCP.

What you see after connecting

Section titled “What you see after connecting”

The rest of the screen fills in as the agent works:

Your tokens, with calls in the last 7 days per token.

  • My usage shows your own calls over 7, 30 or 90 days and your most used tools, packages and clients.
  • Tool reference lists the tools your token gets right now, grouped into your packages, third-party libraries and team knowledge, each with its arguments. It is the live list, so it matches what your client sees.

Troubleshooting

Section titled “Troubleshooting”
Symptom Cause and fix
401 with WWW-Authenticate: Bearer No token, or the token is wrong, expired or revoked. Create a new one.
405 from the endpoint The client sent GET or DELETE. The endpoint is stateless and takes POST only; pick the HTTP transport, not SSE.
A tool answers with a missing permission Your account lacks it on that repository. The answer names the permission; ask an admin, see Permissions.
Fewer tools than a colleague Some tools depend on your access or the token’s scopes (release_step, budget_status).
“Tokens are unavailable” in the panel The instance runs without a key–value store. Ask whoever runs it.
