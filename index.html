How work flows

From a webhook to a merged fix, with a person at every gate.

Every analyzer, review and upgrade goes through the same five stages. Concepts explains each one.

  1. 01 · TRIGGERWebhook or schedule

    A push, a merge request or a cron line from Automation queues work.

  2. 02 · ANALYZEAnalyzers run

    Workers check out the repository with its own tool versions and record findings.

  3. 03 · TASKAgent proposes a change

    A task patches the code, runs CI and opens a merge request per repository.

  4. 04 · APPROVEInbox

    Policies decide what needs a person. It lands in their inbox with the diff.

  5. 05 · SHIPMerge and release

    Merged changes roll into the next release and its changelog.

For agents

Your coding agents read the fleet before they touch it.

The MCP endpoint gives Claude Code, Cursor and any MCP client the same answers the panel shows: public APIs, who uses what, team rules, release state and job logs.

  • Personal tokens from Account › Connect agents, scoped by what the person can see.
  • Rules and conventions come from the repository, so agents follow the team's commit style and test ids.
  • Changes go through tasks: an agent proposes, a person approves in the Inbox.
