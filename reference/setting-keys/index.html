Setting keys

Settings are values that can differ per repository, group or the whole organization. Each key can have entries for several scopes; for a repository, the most specific covering entry wins as a whole (an exact repository, then path globs, subgroups and group intersections, groups, then everything; ties go to the newest). Keys marked global take one value for every repository. Values are never merged field by field, but unset fields of an object keep their defaults.

Settings › Policies and Settings › Analyzers also list keys whose home is another page, and the Search settings field in Settings finds every key wherever it lives. See Settings for the editors and Policies for how scopes resolve.

Note

This page follows the current definitions in the code, which are still moving. The settings editor in the panel always shows what your instance defines, with each key’s help text.

The defaults of each analyzer’s options are in its module docs. The review options are listed on The review agent.

Retired keys

Section titled “Retired keys”

Holtkeeper no longer reads these keys; the panel hides stored entries and refuses new values: llm.model, llm.models, review.instructions, agent.instructions (team rules now live in the Guide), repo.readOnly (replaced by repo.freeze; set freezes again), and the options of removed analyzers analyzers.changelog, analyzers.delivery, analyzers.fleet, analyzers.port, analyzers.quality, analyzers.release-risk, analyzers.warmup.
