GuideSettings

Slack app

In the panel: Settings › Integrations › Slack/settings/integrationsNeeds settings:write

Show the AI review status on every merge request link posted in your channels, and announce new versions with their changes and the repositories an upgrade would break.

The app does two things:

  • Review status. When a message in a channel the app is in links a merge request of a connected repository, the app puts one emoji on the message and keeps it current as reviews run. A message that links several merge requests also gets one status reply in its thread.
  • Release announcements. New versions of a repository get one message in the channels you choose, whatever created the tags.

What it looks like

Section titled “What it looks like”

A new push queues a review, and the emoji goes back to reviewing. Messages with several merge requests show the worst status as the reaction and every status in the thread reply.

Emoji Status When Default Fallback
reviewing A review of the merge request is queued or running :hk-reviewing: :eyes:
clean The latest review says looks good and posted no findings :hk-clean: :large_green_circle:
minor Looks good, with minor or info findings posted :hk-minor: :large_orange_circle:
changes Needs changes, or any major or critical finding :hk-changes: :red_circle:
skipped Not reviewed: the diff is too large or nothing is in scope :hk-skipped: :white_circle:

The defaults are Holtkeeper’s own emoji. A workspace that has not uploaded them gets the standard fallback instead, so the app works before anyone uploads anything.

A message that links several merge requests shows the worst of them: changes, then reviewing, minor, skipped, clean. The status follows the newest review, so an incremental review that finds nothing new shows clean even while earlier findings are still open.

Set up the app

Section titled “Set up the app”

Slack checks the events URL the moment you save it, and Holtkeeper only answers once it has the signing secret. So create the app first, save its credentials in Holtkeeper, and turn events on last.

  1. Create the app from the manifest. At api.slack.com/apps choose Create New App › From a manifest, pick the workspace and paste the manifest below. The full manifest with the long description lives in holtkeeper/.github › slack.

  2. Give it a face. Under Basic Information › Display Information upload the avatar and keep the background #1E140D. Slack rounds the corners itself.

  3. Install and copy the credentials. Choose Install to Workspace, then copy the Bot User OAuth Token (xoxb-…, under OAuth & Permissions) and the Signing Secret (under Basic Information › App Credentials).

  4. Save them in Holtkeeper. Open Settings › Integrations › Slack, paste both and save. They are sealed with the server’s vault key and never shown again. The section then shows the request URL to copy.

  5. Turn events on. In the Slack app, Event Subscriptions: paste the request URL (Slack verifies it at once), add the bot events message.channels and message.groups, save, and reinstall when Slack asks. You can add the same block to the manifest instead:

  6. Invite the app to each channel it should watch: /invite @holtkeeper.

  7. Bind channels to repositories (next section).

Scope For
channels:history Read messages in public channels the app is in, to find merge request links
groups:history The same in private channels
reactions:write Set the review status emoji
chat:write Post status replies and release announcements; reactions work without it

Behind a NetworkPolicy or egress proxy

Holtkeeper calls https://slack.com/api from both web and worker pods: a review that finishes on a worker updates the emoji from there. Allow slack.com for both roles.

Bind channels

Section titled “Bind channels”

The slack.reviews setting maps a scope to Slack channel ids. The most specific entry wins as a whole: an entry for everything sets the default channels, a group or repository entry replaces them for its repositories, and an entry with no channels keeps a group quiet. A message about a repository is handled only in a channel bound to it, so groups can share channels or keep their own.

Use channel ids, not names: open the channel’s details; the id is at the bottom of About. Private channels may start with G.

Use the Holtkeeper emoji

Section titled “Use the Holtkeeper emoji”

Download the set from holtkeeper/.github › slack › emoji and upload each file under Customize workspace › Emoji with its own name (hk-reviewing, hk-clean, hk-minor, hk-changes, hk-skipped). Nothing else to set: the app uses them as soon as they exist. Until then it adds the standard fallback and remembers that the workspace lacks the custom one.

All five are 128 × 128 with a transparent background. Only reviewing is animated, so a channel of finished reviews does not flicker; hk-reviewing.png is its still twin for workspaces that turn animation off.

Your own emoji

Section titled “Your own emoji”

To show different emoji, enter their names under the tokens in Settings › Integrations › Slack. Overrides are used as given, without a fallback, so make sure the workspace has them. Blank fields keep the defaults; a changed emoji shows on a message the next time its status changes.

Release announcements

Section titled “Release announcements”

With releases.announce set for a repository, its new versions get a message in the listed channels — whether the tags come from Holtkeeper’s version step, changesets, release-please or a CI job. Tags found within ten minutes of each other make one message. The app needs chat:write and an invitation to those channels.

Field Default What it does
channels none Slack channel ids; without any, nothing is announced
tags flow tags + packages Glob patterns of tag names such as @acme/*@*
groupWindowMinutes 10 Tags found within this many minutes of the first make one message
notes on AI notes: overview, highlights, breaking changes with migration hints
tasks on Tracker tasks named by the commits
impact on “Will break on upgrade”: connected repositories whose code uses what the version removed
language review language Language of the AI prose; code and technical terms stay in English

The first look at a repository records every existing tag as seen, so history is never announced. When the compatibility analysis is not ready, the message goes out with Compatibility analysis is still running and is updated in place once it lands. When the AI budget blocks the notes, the message goes out without them.

Nothing shows up?

Section titled “Nothing shows up?”

The app stays silent, and stores nothing, when:

  • the link’s host is not a configured forge, or the repository is in no group;
  • Merge request reviews are off for the repository;
  • the channel is not bound to the repository, or the app was not invited to it;
  • no Slack credential is saved.

A merge request with no review yet gets no emoji until its first review is queued. When reviews are turned off or a channel is unbound after a message got its emoji, the emoji is removed at the merge request’s next review change. Messages older than 30 days stop changing.
