Guide

Getting started

Holtkeeper is a self-hosted automation engine for fleets of GitLab and GitHub repositories. Everything it does — review, audits, dependency waves, release analyses — runs from one command line and from a server that queues the same work on webhooks and schedules.

Requirements

Section titled “Requirements”
  • Bun 1.4. Holtkeeper has no build step: packages export TypeScript source and Bun runs it directly.
  • mise for the tools some commands call: osv-scanner, gitleaks, Go and pnpm are pinned in mise.toml.

Run from source

Section titled “Run from source”

bun install also sets up the git hooks. The rest of this page writes holtkeeper for bun apps/cli/src/bin.ts.

Audit a checkout

Section titled “Audit a checkout”

audit scans a directory with OSV-Scanner and prints every finding that is not allowlisted. With --fix it runs the fixers in order — osv-scanner fix, then the JavaScript fixer (bun, pnpm, yarn, npm), then the Go fixer — and scans again.

It exits with 1 while unfixed findings remain, so it fits a CI job as is. See @holtkeeper/cli for every option and @holtkeeper/vuln for the allowlist format.

Run an analysis

Section titled “Run an analysis”

analyze <kind> runs one analyzer and prints its report; --json prints the data instead.

holtkeeper --help lists every kind with its flags: changelog, bundle, depgraph, quality, coverage, testids, licenses, release-risk, fleet, stack, assets, delivery, branches, i18n, propagate, port and review. Analyzers that use an LLM take --model and need ANTHROPIC_API_KEY.

Describe your fleet

Section titled “Describe your fleet”

Everything else reads holtkeeper.config.ts: forges, repository groups, plugins and the server section.

validate-config checks the file without secrets, explain prints what applies to one repository, and serve starts the API, the admin panel and the task engine on port 7420. @holtkeeper/core documents the config and @holtkeeper/server the server section. For containers, deploy/ holds a Docker Compose file and a Helm chart that run the same image as web, worker and scheduler processes.
