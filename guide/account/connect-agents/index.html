GuideAccount

Connect agents

In the panel: Account › Connect agents/account/agents

Issue personal MCP tokens, add Holtkeeper to Claude Code, Cursor or any MCP client, watch your own usage and browse the tools your agents get. Every signed-in person can connect agents; a token reads by default and acts as you.

Create a token, add the server to your client, ask about your code.

Create a token

Section titled “Create a token”

Use one token per machine or agent, so you can revoke one without breaking the others.

  1. Click New token in the header.
  2. Name it after the machine or agent, for example laptop.
  3. Pick when it expires: 30 days, 90 days, 1 year or never.
  4. Leave both switches off for a read-only token, or turn on what the agent needs:
    • Release steps lets it propose, accept, version and deploy releases.
    • Run tasks lets it start code-changing tasks and request reviews without waiting for a person to approve.
  5. Create it and copy the secret now; it is not shown again. The dialog also shows the ready Claude Code command.

A token acts as you with read access to repositories, analyses, audits, knowledge and releases, plus releasing or running tasks when you turned those on. It never gets more than your own grants. With Holtkeeper’s own accounts it follows your current grants, and disabling your account or signing out everywhere revokes it.

Caution

A token authenticates only the MCP endpoint and the read-only catalog API. It cannot issue or revoke tokens. Revoke a token you no longer use from its row.

Token status

Section titled “Token status”
Status Meaning
Active Valid and used.
Expires soon Expires within 14 days.
Expired Past its expiry; create a new one.
Never used No call has used it yet.

The name filter above the table narrows long lists. Calls, 7 days counts each token’s calls.

See your usage

Section titled “See your usage”

My usage shows your own calls over 7, 30 or 90 days.

A daily chart shows answered over failed calls. Tool calls do not call a model, so they cost nothing from the AI budget. With ai:read, a link leads to everyone’s usage on Ops › AI spend.

Browse the tool reference

Section titled “Browse the tool reference”

Tool reference is read live from the endpoint, so it lists exactly the tools you get. Tools are split into Your packages (exports, versions, usages and upgrade impact of what your repositories publish), Third-party libraries (whether to add or upgrade a dependency, and the docs, changes, issues and source of libraries at the version each repository uses) and Team knowledge. Each tool shows its description and arguments, and the list can be filtered.

Note

Agents can propose knowledge and rule changes, but people review them in Knowledge. No MCP tool approves tasks or makes other Inbox decisions.
