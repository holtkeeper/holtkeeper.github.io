GuideSupply chain

Stack

In the panel: Supply chain › Stack/supply/stackNeeds catalog:read

See which runtimes, package managers, services and base images every repository uses, which release lines reach end of life, and whether each repository still matches its group’s convention files.

Each cell is the version a repository uses, toned by its support.

What the page shows

Section titled “What the page shows”

The stack is analyzed per group: once a day, every repository of the group is read through the forge, without a clone, and the versions found are compared with the latest releases and their end-of-life dates. The page shows the current state.

Kind Examples Read from
runtime node, go, python, java version files (.nvmrc, .tool-versions, mise, go.mod), images, CI setup steps
package-manager pnpm, npm, yarn, bun packageManager, version files
service postgres, redis, rabbitmq compose files, CI services, deployment YAML
os alpine, debian, ubuntu image tags
image your base images Dockerfiles, compose, CI and deployment YAML (Helm values*.yaml, k8s, charts, …)
tool any other mise tool version files

Support reads the same everywhere: end of life, ends soon (within 180 days by default), LTS, active or unknown. A floating version such as 22 counts as current while the latest is any 22.x.

A line under the tabs sums each group’s changes over the past week.

Runtimes

Section titled “Runtimes”

Runtimes is a repository × tool matrix. Narrow it with the support segment (all, ends soon, end of life) and the Kind filter; the scope switch narrows groups. Below the matrix, Version lines lists each tool with its latest version and the lines in use as chips with their repository count.

Upgrade a release line

Section titled “Upgrade a release line”

A line chip or a matrix cell opens the line sheet.

  • Where declared lists the repositories on the line, what each writes and where. Each repository links to its hub.
  • With a cell picked, Selected cell adds that repository’s versions, the suggested upgrade steps and the convention its file is checked against.
  • Plan upgrade with agent appears when a newer line is suggested and you have tasks:run. It starts one upgrade task group that moves every repository on the line to the first suggested step, with the spend cap and the write-task checks of any rollout.

Conventions

Section titled “Conventions”

Conventions are golden files every repository of a group should match: an .nvmrc, a shared lint config, a CI include. Conventions is a repository × file grid.

A cell opens its problems and the suggested fix as a diff:

Open merge request (needs analyses:run) opens the fix in that repository. Problems and diffs show only for repositories you may read analyses of; elsewhere you see how many differences there are.

Define a convention

Section titled “Define a convention”

Conventions are set per group in the analyzers.stack setting, which the panel edits as a form under Settings › Analyzers.

Mode Matches when Suggested fix
exact the file equals the golden content replace the file
json-subset every key and array item of the golden JSON is present and equal in-place edits, comments kept
yaml-subset the same for YAML in-place edits
lines-present every non-blank golden line appears, in any order append the missing lines

Note

Conventions are exact files on purpose: no model writes or judges them.

Run a scan

Section titled “Run a scan”

Run stack scan queues a new analysis instead of waiting for the daily one. Other analyzers.stack options: ignore (tools or images to leave out, such as image:registry.example.com/*), soonDays (default 180) and lookups (off only collects what repositories use, without latest versions).

Caution

Helm templates and Kustomize overlays are not rendered, image tags that are code names (bookworm) count as unpinned, and unquoted YAML versions like 3.10 read as 3.1. Quote them.

In a group

Section titled “In a group”

A group page’s Stack & conventions tab shows the same view for one group. The repository hub’s stack link opens that tab for the repository’s group, or this page when the repository is in no group.
