DevelopCore & contracts

@holtkeeper/api

packages/api/docs/README.md

The HTTP contract between the server and its clients (web UI, CLI): request and response types for every endpoint, plus small pure helpers both sides use. It contains no server code and is safe to bundle for browsers.

Helpers

Section titled “Helpers”
  • summarizeRun(run) — the numbers lists and charts show: active findings by severity, fixed, allowlisted, expired allowlist entries, changed files, and the languages and package managers involved.
  • sourceInfo(source) — which package manager and language a finding’s file belongs to (pnpm-lock.yaml → pnpm / JavaScript, go.mod → Go modules / Go, uv.lock → uv / Python, …). This is what makes reports look the same for every ecosystem.

Settings files

Section titled “Settings files”

The types of the Settings endpoints sit in one file per area, each exported from index.ts: settings-people.ts (PeopleSummary), settings-ai.ts (Settings › AI and Integrations: AiBudgetOverview, AgentToolList, IntegrationForgeList), settings-analyzers.ts (AnalyzerHealthList of GET /api/jobs/analyzers/health, PolicyDraftInput/PolicyDraftResult of POST /api/settings/draft, CommitConventionsCheckInput/CommitConventionsCheckResult of POST /api/commit-conventions/check) and settings-system.ts (SystemHealth of GET /api/system/health, HistorySummary of GET /api/history/summary, AuditVerifyLast of GET /api/audit/verify/last). Fields shared views gain for Settings (MeResponse.version/publicUrl, UserView.lastSeenAt/invite/teams/creator, CredentialView.usedBy/lastUsedAt) are optional, so a server that does not fill them yet still matches. InboxBudgetItem (kind: 'budget') is the weekly AI budget warning.

RepoSummary carries the repository’s health: health (RepoHealthStatus: healthy, warnings, failing or not-analysed, over the cells the caller may read), cells (RepoHealthCells, each a RepoHealthCell { value, sub, tone } with HealthTone ok, warn, bad, info or none; security needs audits:read, release releases:read, the rest analyses:read, and a cell the caller may not read is absent), freshness (RepoFreshness { current, total }) and lastAnalysedAt with analyses:read, updates (RepoUpdatesSummary { via, intervalMs?, lastPolledAt?, lastError? }) with settings:read on the repository, latestAudit with audits:read, and configurable with settings:write. DependencyTable has one row per library the caller’s catalog reach uses (direct dependencies of the newest depgraph records and imports of the newest usages records), with versions per repository, latest, how far behind, advisories, licenses and Renovate state, plus the repositories with their config groups; repositories are named forge:path. MeResponse.crossTeam is the access.crossTeam level, so clients know whether any read grant reaches the catalog. MeResponse.groupTitles maps group keys to their display titles (only titled groups the principal may know about: all with global settings:read, otherwise those its grants name or its listed repositories belong to; empty when signed out); clients show the title wherever a group appears and keep the key as its identity. GroupDocumentData.title is that optional display name.

Supply chain endpoints answer from stored metrics of the newest records and only for repositories the caller may read. FindingsResponse groups the newest audit of each repository by advisory and package: a FindingGroup lists its repos (FindingRepo with versions, sources and its own FindingStatus), fixedIn, firstSeenAt (when an audit first reported it, or the record time where no first sighting was stored) and a group status that is open while any repository has it open, else fixing (with taskId) while an approved, queued, running or mr-open dependency-upgrade task upgrades that package, else allowlisted while an unexpired allowlist entry hides it; severities counts groups of every status. LicensesOverview has kpi totals (package and internal counts and the license mix add up each repository’s counts, so a package used by two repositories counts twice; verdict and license counts are distinct across the fleet), the license mix, violations (worst verdict across repositories: denied, unlisted meaning needs review, or unknown), one LicensesRepoRow per repository with counts per LicenseVerdictName, the organization-wide policy with the number of narrower overrides (only for callers who may read the organization’s analyzers.licenses entry), and deltas against each repository’s newest scan at least a week old. DependencyApi says where an internal package is defined (definedIn) and counts its exports and documented ones; DependencyDetail also answers for an internal package only the public API catalog knows, with empty lists, and leaves upgrade readiness to GET /api/dependencies/upgrade. StackTool.cycles lists the component’s release lines (StackCycle) when its lifecycle is known.

Public API lists carry facets (PublicApiFacets: kinds, packages and repositories, plus subpaths and match kinds for search) counted before the facet filters apply. Every search hit says how it matched (PublicApiMatch: exact, prefix, part, doc), whether the symbol is deprecated, whether its package was removed and the release ref it was read from; a package summary has match when the list was filtered by q. PublicApiSymbol is one symbol in full with a history capped at limit versions (default 20, at most 100) of the recorded versions where it was added, changed, deprecated or removed (capped says older versions were left out).

SettingDefinitionView.default is what applies where no entry covers a repository (null when nothing applies until someone sets the key). ResolvedSettings is for one focus, a repository (repo) or a group (group, standing for a member no narrower entry names), and keeps settings (winner per key with an entry) and cascade (every covering entry per key) and adds rows: one ResolvedSettingRow { key, label, section, value, source, replaces?, entry?, overrides } per defined key, in definition order. source is a SettingSource { layer, groups?, entry? } with SettingLayer default, org (an entry for everything), group (groups names the focus’s groups the entry matched) or repo (a path pattern matched); replaces is the next broader source with its value, the default when nothing broader covers the focus, absent when the default wins; overrides counts the broader entries the winner beats. Retired keys, keys without a definition, secret settings and releases.notify get no row, a global key only shows org or default, and analyzers.<kind> is one row whose entry applies as a whole, never merged field by field. It needs settings:read on the repository or the group.

InboxItem is a union on kind (task, note, learning, guide, release, allowlist); every item has a stable id (<kind>:<source id>, also what a snooze names), scope as people read it, repos, href, createdAt, snoozed and the ids a decision needs (groupId, entryId and version, learningId, guideScope with section and inputHash, repo with head and can, settingId with the allowlist entry and expires). InboxFeed.mine holds what the caller may decide in their home groups and teams the rest; without home groups everything is in mine. InboxCount leaves snoozed items out. Inbox decisions are not available through MCP.

ReleaseCard.can is computed per caller (accept and run need releases:run; Accept is offered only with can.accept), head is the commit a dismissal names and dismissed holds until a new commit arrives. HomeAttentionItem.snoozed marks items the caller snoozed.

AiUsageOverview reports one period (week, month or 30d): current from its start to now and comparison over the same elapsed span of the previous period. Spend forecasts (AiSpendForecast, AiBudgetStatus.forecastUsd, HomeSpend.forecastUsd) are this week so far plus the mean of the rest of the week over the last 4 full weeks, never a linear projection; automaticStopsAt is when automatic work is expected to reach the budget minus its reserve.

Phase-19 views state their guarantees in TSDoc. ChatThreadView.contextRepos and ChatMessageView.refs only carry repositories the caller may read; ChatThreadContextView.costUsd is present only with ai:read, and the repositories the caller may not read are only counted (hiddenRepoCount). ChatThreadList.archivedCount counts visible archived threads matching q. Task cards in ChatMessageView.card leave out the steps and merge requests of repositories the caller may not read, and a task in none of the caller’s repositories reads as a neutral line. ChatThreadPatchInput.muted is per caller. KnowledgeCounts.spaces holds only spaces the caller may read. GuideChainSection.layers are numbered in the order the agent reads them (repository files, repository rules, family, groups in config order, all repositories, learnings, policies, generated text, notes) under the 12000 / 8000 / 4000 character budget. LearningCandidateView.confidence is deterministic (1 plus one point each for at least 2 discussions, 2 authors, 2 repositories and 3 authors, at most 5). AcceptLearningsResult reports each id as accepted or failed; one failure never stops the rest.

ChatMessageList.cursor is the after of the next poll and serverTime its changedSince; a client advances the cursor only from message pages, never from a message it posted, and expects repeated messages because serverTime trails the clock.

RepoUpdatesView.webhook keeps the repository webhook’s last 50 deliveries, newest first (a rejected one has error and queued nothing), deliveries24h counts those of the last day and how many failed, and createdBy names who issued the URL. GroupListingView.matched is what the include patterns matched in the last listing before excludes, so a page can preview unsaved patterns; it is sent only to callers with global settings:write; nextAt is when the next scheduled listing is due.

Quality endpoints answer for repositories the caller may read, from stored metrics of a bounded number of the newest records; record data is read only for one repository or record. CiRepoCard carries groups, status (CiStatus), flakyJobs, queueMedian and, only with releases:read on the repository while releases are on, releaseGate (CiReleaseGate). CiJobsView returns at most a fixed number of job rows over a bounded range; total and outcomes cover every job of the range. BundleTargetRow judges budget and verdict against the current analyzers.bundle options and carries the target’s series over the records read (BundlesRepoRow.records, about 20). AssetsOverview pages files: items is one page, total counts every match, nextCursor is present exactly when more pages follow, and repos ignores every filter but group and repo. ReviewList pages by nextBefore; ReviewRow.model and durationMs are absent and guideScopes empty for records made before they were stored. BranchesRepoRow.delta compares with the previous record’s metrics and is absent without one. AnalysisDetail.job names the job that produced the record, absent for uploads. MediaVariantsResult.exists says for every variant path whether it already exists at the ref.

Errors are ApiError { error } with status 400, 401, 403, 404, 410 or 500.

Every 403 is a ForbiddenError { error, missing: { action, target? } }: the Action the request needed and, when it was about one repository, target as the repo key (forge:path) the client sent. It never names groups or grants, and it reads the same whether that repository exists or the caller may not see it. MCP tool refusals carry the same body as structuredContent.

LinkInfo describes a live, unused setup or recovery link before sign-in: purpose, userName, expiresAt and grants: { count, role }, where LinkRole is the broadest preset the grants reach (viewer, developer, maintainer, admin); scopes, group names and who issued the link are never included. A used or expired link answers 410 with LinkGone { error, state: 'used' | 'expired', at }.
